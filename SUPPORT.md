# Support

Thank you for using this project. This document explains how to get help, report problems, and request features.

## Documentation

Before requesting support, read the project documentation:

- Installation Guide
- Getting Started
- Architecture Overview
- Storage Engine
- Query Engine
- Query Language
- Graph Algorithms
- Performance
- Deployment
- Frequently Asked Questions (FAQ)

Most common questions are already answered there.

## Bug Reports

Open a GitHub Issue with:

- Operating system
- Project version
- Architecture (x64, ARM64, etc.)
- Steps to reproduce
- Expected behavior
- Actual behavior
- Error messages
- Logs (if available)
- Screenshots (if applicable)

A minimal reproducible example greatly helps the investigation.

## Feature Requests

Feature requests are welcome. Please explain:

- The problem you are trying to solve
- Why the feature would be useful
- Possible implementation ideas (optional)
- Any alternatives you have considered

Clear, well-justified requests are much easier to evaluate.

## Security Issues

**Do not report security vulnerabilities through public GitHub Issues.** Follow the instructions in [SECURITY.md](SECURITY.md). Responsible disclosure protects all users.

## Questions

If your question is not a bug or feature request:

1. Read the documentation first
2. Search existing GitHub Issues and Discussions
3. Open a GitHub Discussion if no answer is found

This keeps the issue tracker focused on actionable development work.

## Before Opening an Issue

Please verify:

- You are using the latest supported version
- The issue has not already been reported
- The documentation has been reviewed
- The problem can be reproduced consistently

## What We Support

- Latest stable release
- Current development branch (`main`)
- Officially documented features

Support for older releases may be limited.

## Response Expectations

As an open-source project maintained in available free time:

- Response times are not guaranteed
- Complex issues may require additional investigation
- High-quality reports are prioritized

We appreciate your patience and understanding.

## Community Guidelines

Be respectful and professional in all interactions. Constructive discussions and thoughtful feedback help improve the project for everyone. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for community expectations.

## Thank You

Whether you're reporting a bug, suggesting an improvement, improving documentation, or contributing code—your support helps make this project better for everyone.
